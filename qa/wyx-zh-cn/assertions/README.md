# Assertions

为 Skill Creator 的运行定义客观检查项。把断言复制进 `../evals/evals.json` 的每个 eval。

本技能的断言要覆盖四类判断：

## 启用策略

- 在 Codex 中，技能只在用户显式指名 `$wyx-zh-cn` 时启用；普通的架构、模块边界或漂移请求不自动触发。

## 模式路由

- 用户只说「想开始用 wyx」且项目无规格 → 走审计模式，不直接生成规格。
- 用户给出模块路径 → 走回填模式，先读代码再提规格。
- 用户给出功能描述而非路径 → 走新建模式，并在存在多个目的时强制拆分。
- 用户说「查漂移」→ 走漂移模式，且第一阶段只读。

## 写入纪律

- `wyx:concept` / `wyx:pipeline` / `wyx:sync` 在用户确认前不落盘；文件已存在时先给 diff。
- `wyx:audit` 全程只读，绝不产出规格文件。
- `wyx:map` 可直接覆盖 `ARCHITECTURE.md`，无需确认。
- 漂移的修复动作发生在第二阶段，且必须经用户批准。

## 严重度纪律

- 严重度逐字取自检查表，不因主观影响判断而上调。
- 私有辅助函数、命名风格差异、实现细节状态字段一律 Low。
- 未记录的跨概念内部访问是 Critical；已写进 `## known coupling` 的降为 Low。
- 「规格没提到」不等于「规格被违反」——不得据此报矛盾。

## 交互纪律

- 用户已经说明范围、是否落盘、改规格还是改代码 → 不重复追问。
- 缺少阻塞性信息（模块路径缺失且无法从上下文推断）→ 只问一个问题，不做问卷。
