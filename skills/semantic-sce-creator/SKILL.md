# 场景-概念-实体萃取

把线性原文变成可调用的知识元。概念是中枢：先给出可执行定义，再驱动实体挂接与场景组装。价值在调用。三层划分灵感来自「人月聊 IT」《三层架构：场景、概念与实体》。

工作目录：用户指定；三个 yaml 文件名固定：

| 层 | 文件 |
| --- | --- |
| 场景 | `sce-scenes.yaml` |
| 概念 | `sce-concepts.yaml` |
| 实体 | `sce-entities.yaml` |

进度：`_sce-round1-progress.md`。

## 三层（定义即生成器）

- **概念 = 类 = 可执行动作**。回答「用什么方法来想」。合格定义：IPO（输入→处理→输出）保独立逻辑；分解（阶段、子概念、该步为何需要）建调用。可并用。写不出则过虚并入父概念，或过碎降为步骤。
- **实体 = 实例 = 可指认对象**。回答「用什么人/工具/产品/具名框架」。口诀：「我用了 X」且 X 不是动作本身。通用动作→概念；有提出者的方法论产品→实体。
- **场景 = 组装 = 问题 + 编排规则**。回答「如何……」。只调用已成立的概念与实体：触发、目标、3–6 个递进阶段、每阶段调用与约束。

## 关系（8 种，少而准）

边要能支撑后续组装。每概念 2–6 条。离开对方仍能独立工作 = 参考，不是依赖。

| 类型 | 方向 | 何时用 |
| --- | --- | --- |
| 包含 | 概念→概念 / 实体→实体 | 整体与部分 |
| 依赖 | 概念→概念 | 离开则无法执行 |
| 参考 | 概念→概念 | 仅提及，可独立工作 |
| 调用 | 场景/概念→概念或实体 | 组装或执行时使用 |
| 分解 | 概念→子概念 | 流程性概念的阶段 |
| 父子 | 实体→实体 | 层级，≤3 层；子项须独立来源、独立定义、可被单独引用 |
| 组装 | 场景阶段→概念/实体 | 阶段规则 |
| 别名 | 知识元→名称 | 命名变体，不另立条目 |

## 第一轮：快速扫描 · 提取骨架

按序每批 5–10 篇（或等价篇幅），进度写入 `_sce-round1-progress.md`。

1. **读原文** → 本批读完并记下进度。
2. **抽候选**（只写 `id + define + sources`）：场景=「如何……」；概念=能否 IPO 化；实体=「用了 XX 吗」。`define` ≤50 字，须出自原文。
3. **全局去重**：语义重叠≥80% 合并；同义统一 id；过细步骤收回父概念。记合并日志（X→Y）。
4. **产出骨架**：写入 `sce-scenes.yaml`、`sce-concepts.yaml`、`sce-entities.yaml`，其余字段标 `TODO`。
5. **停，等人确认**：出示去重结果与概念覆盖。未确认不进入第二轮。

本轮完成：只有骨架，无冗余，有去重日志。

## 第二轮：内容填充 · 完整建模

用 `sources` 回查对应段落。信号词：先/然后→步骤；需要/输入→IPO 输入。

1. **按中枢填充**（先概念，实体并行，后场景）。概念写满 IPO 或分解；场景写触发+目标+组装。原文无依据则留空，不编造。
2. **补关系网**：上表 8 种；实体补层级；概念↔实体用调用。
3. **完整性校验**：引用可解析；`define` ≤50 字；无孤立概念。
4. **收口**：`sce-scenes.yaml`、`sce-concepts.yaml`、`sce-entities.yaml` 填满，写 `updated_at`。

本轮完成：引用可解析、条条有出处、通过校验。

## 五原则

1. **原文至上**：`define` 与 IPO 来自原文。
2. **宁缺毋滥**：原文写不出 IPO/分解就不填。
3. **框架适中**：没有自己的 IPO 或分解，不独立成概念。
4. **引用可控**：每概念 2–6 条关系。
5. **表述精炼**：一句说清的不写两句；过碎步骤收回父项。

## 完成标准

- 概念可执行：能被另一个场景直接调用
- 场景可指导行动：换同类问题能按阶段走
- 实体有定位与关系网
