# process.md — 七阶段协作流程与场景适配

三个「讨论」阶段是硬闸门：没拿到用户明确确认不进下一阶段。返工最大来源是跳过阶段 1、2 直接搭页。本文只管流程与产出；HTML 写法见 `deck-format.md`，页型见 `page-patterns.md`。

## 0. 场景适配表

阶段 1 问清场合后先按此表定基调；后文经验值按表换算。

| 维度 | 授课 / 培训 | 汇报（进展 / 方案 / 述职） | 学习材料（自读） |
| --- | --- | --- | --- |
| 叙事骨架 | 抛问题 → 讲原理 → 看实践 → 巩固收尾 | **结论先行**：背景一页 → 结论 / 诉求 → 论据与数据 → 风险与下一步 | 手册式：总览 → 分主题展开 → 速查小结 |
| 页数节奏 | 1.5–2 分钟/页；40 分钟 ≈ 20–25 页 | 用时长的**一半**做页数预算（10 分钟 ≈ 5–8 页），备查内容进附录 | 不受时长约束，按主题完整性定页数 |
| 页型倾向 | 全部可用；问题页 / 研讨页 / 动手实验穿插互动 | 截图对照、表格混排、密集多栏、全幅大图、数据大字；**不用**研讨页 / 题卡 | 各版式可用；金句页做章节小结 |
| 官方页型倾向（huawei 风格） | 章扉 + 卡片网格 + 流程条 | 1-2-1 痛点方案价值、AS-IS/TO-BE 对比、KPI 数字带、案例五段式、附录矩阵 | 目录复用作章节过渡、速查表 |
| 字号档 | 散文 ≥21px | 短语卡 ≥18px、数字大字 ≥64px | 散文 ≥21px（读者自读） |
| 动画用量 | 按讲课节拍整拍设计 | 少用或不用（常被打断、常导 PPTX） | 不用（无讲者推进） |
| 语言风格 | 口语化，可类比、设问；页面留钩子 | 书面结论化：判断句 + 量化数字（写「提升 1.76×」不写「快了很多」）；不用类比、设问、emoji | 完整自解释句子，忌电报式短语 |
| 交付形态 | HTML 放映为主 | **PPTX 常是硬要求**，阶段 4 就试导一次 | HTML 单文件分发 |

## 1. 主题讨论

用户往往一句话提需求。开工前**五件事一次问完，不挤牙膏**：

1. **听众**：背景、人数、对主题的熟悉度（决定深度与术语量）
2. **场合与时长**：授课 / 汇报 / 自读？现场讲还是发出去看？多少分钟？
3. **目标**：听众离场时该记住 / 会做什么（决定主线）
4. **素材**：文档、数据、截图、旧 PPT、外链（决定哪些页有真料）
5. **风格与交付**：列出已装风格（`styles/` 目录）让用户选；用户提到公司 / 品牌名直接匹配；未说明默认 `generic`。密级 / 页脚文字、logo 是否替换；交 HTML 还是 PPTX

产出：把五点整理成一段**需求共识**复述确认，不自己脑补。

**快答模板**（用户催「直接做」时）：每件事给出默认假设，用户只需纠偏（回「都对」即开工）。加速的是讨论形式，不豁免闸门。

> 听众：研发同事、熟悉基础概念 · 场合：15 分钟汇报 · 目标：接受方案 A 并批准资源 · 素材：你给的 PRD + 两张截图 · 风格：generic，交 HTML+PPTX（截图版）。对吗？

## 2. 大纲规划

- 骨架按场景表选；每章分配分钟与页数预算。
- 产出大纲表：章号 / 章名 / 要回答的问题 / 分钟 / 页数。**确认前不写页面。**
- **确认后立即落盘** `<deck>.plan.md`（格式见 SKILL.md 输出格式），别只留在对话里。章级几行，逐页表阶段 4 补。

## 3. 选择页型

拿大纲逐条映射到 `page-patterns.md` 目录。固定三页不可选、不可替代：第 1 页 `cover`、第 2 页 `toc`、末页 `thanks`；目录条目按实际大纲生成。节奏检查：

- 每章开头一张章扉；重点章前抛一张问题页（≤15 分钟的短汇报省掉章扉或只留一张）
- **连续 3 页同一视觉家族即返工**——换卡片数量不算换版式；在 网格 / 分栏 / 流程 / 矩阵 / 证据 / 全图 / 观点 家族间切换
- 同页两个以上耦合维度（阶段 + 责任 + 交付物；系统 + 证据；代码 + 曲线 + 指标）选 `dense` 复合页型，不拆成多页薄卡片
- 密页后接轻页（全幅大图 / 金句）换气
- 有真素材的内容优先选「用真料说话」的页型（截图对照、代码曲线指标）

产出：页型映射表（大纲条目 → 页型 → 视觉家族 / 密度 → 理由一句），通常与阶段 4 逐页表合并。

## 4. 初版

**先规划后动手。** 逐页规划表每页一行：`# | label | 核心观点 | 页型 | 家族/密度 | 配图 | 拍数`。

- **核心观点 = 这页存在的理由，一句话**。写不成一句说明该拆；两页同一句说明该合。
- **配图初版就定类型**：原图 / 自绘·流程 / 自绘·架构 / 表格 四选一，落成页面上的类型化占位块（`visuals.md` §1）；确实无图写「无」，不留空。
- 拍数先标 1，动画终版再精修。
- 文案按终版口径写（场景表语言栏），别先写口水稿；标题句式与禁用词见 `style-guide.md` §4。

然后按 `deck-format.md` 写 `<deck>.html`：复制骨架 → 填内容 → 每写完一章用浏览器 `?debug` 看一次。交付含 PPTX 时（汇报常见）**初版就试导一次**，转换问题要在结构讨论前暴露。

产出：初版 deck + 逐页表写进 `<deck>.plan.md`「逐页」节（之后就是讲稿骨架与跨会话修改依据）。

## 5. 讨论修改（初版）

- 把 deck 与逐页表一起给用户在浏览器里过一遍。
- **逐章引导反馈**，别只问「你看看怎么样」：每章问「观点顺序对吗？哪页增删？」
- 意见按页记录成修改清单，改完逐条回报（改了什么、在哪页、debug 是否干净）。
- 结构性意见（挪章、删线索）在这一轮消化；终版只做精修。

闸门：用户明确点头「结构定了」。

## 6. 终版

按顺序，每步完成即验证：

1. **配图落地**（`visuals.md` §2–4）：逐个替换占位块，`data-todo` 归零
2. **动画节拍**（仅授课，`motion.md`）：按讲课节奏整拍设计；汇报 / 自读跳过
3. **品牌收口**：页脚、logo、密级文字按风格文件与阶段 1 答案填齐
4. **全量验证**：`?debug` 无红框；重点页与深色页截图目检（如宿主有浏览器工具）；动画页逐拍手动过一遍
5. 需要 PPTX：`tools/export_pptx.py`，抽查 layer 多标签页是否逐标签展开

## 7. 讨论修改（终版）

- 只接受精修：文案措辞、数字核对、页序微调；结构性返工回阶段 5 重新走闸门。
- 确认交付形态；提醒放映键位（`motion.md` §1）；附一句怎么自助改文案（直接编辑对应 `<section>`）。

## 常见错误

| 错误 | 纠正 |
| --- | --- |
| 跳过 1、2 直接搭页 | 改用带默认值的快答，不跳过 |
| 大纲只留在对话里 | 确认后落盘 `<deck>.plan.md` |
| 拿授课节奏做汇报 | 页数减半、结论先行、细节进附录 |
| 给汇报 / 自读堆动画 | 汇报少用并先试导 PPTX；自读不用 |
| 语言与场景错位 | 汇报里出现类比、设问、口语 → 按场景表校一遍全文 |
| 套话、广告词、自造比喻 | 换成具体事实与数字；机制写「动作 + 技术名称」 |
| 栏目式 / 悬念式标题 | 写成含技术名词的判断句（`style-guide.md` §4） |
| 一页多个核心观点 | 拆页 |
| 初版就抠图、调动画 | 结构没定精修全是沉没成本；占位块足够讨论 |
| 占位块不写类型与规格 | 第一行类型 + 来源，第二行内容 + 比例 |
| 方法论页全是文字卡 | 自绘图做主表达，原图给证据 |
| 改完不看 `?debug` 就给用户 | 溢出裁切是无声的 |
| 终版接受结构性返工 | 回阶段 5，否则「终版」无限循环 |
