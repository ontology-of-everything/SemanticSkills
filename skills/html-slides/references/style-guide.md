# style-guide.md — 风格无关的硬规

本文的规则对所有风格生效；具体色值、字体名、圆角与阴影取值由 `styles/<style>.md` 的变量块提供，本文只用变量名。与风格文件冲突时：**投影可读、论证结构**相关以本文为准，**看起来像谁**相关以风格文件为准。

## 1. 颜色使用规则

变量含义见 `deck-format.md` §2。使用纪律：

- **强调色只给真重点**：`--accent` 用于标题强调、关键数字、当前 / 选中 / 风险 / 结论差异；平等并列项不上色。一页强调处 ≤6。
- **去花花绿绿**：外部素材、图表、自绘图搬进来先映射到 `--accent` / `--accent-2` / 中性灰三档；图表数据编码按图例用色，不拿来装饰卡片。
- 真实产品截图**保留原生配色**，不改色。
- 深色 profile 下按风格文件规定的「工作色」做信息强调（例如 huawei 深色用金色），不要把大面积 `--accent` 铺到深底上。

## 2. 字体规则

- 中文一律走 `--font-sans`；**任何可能出现中文的元素不得只挂等宽字体**（无中文字形会回退成细体，投影看不清）。
- `--font-mono` 只用于数字、英文、代码、编号小标签（eyebrow、徽标）。
- 加粗用 `font-weight`，不靠换字体。
- 字体走系统字体栈（`deck-format.md` §2），不内联字体文件、不依赖网络。

## 3. 字号：一套刻度 + 场景地板

- **唯一刻度**：正文区只用 `{13, 15, 17, 19, 21, 24, 27, 30}`；标题 ≥34；数字大字 ≥64。禁止 `16.5px` 类手调值。
- **场景地板**（给听众 / 读者读的散文的最小值）：

| 场景 | 散文地板 | 说明 |
| --- | --- | --- |
| 授课 / 培训 | 21px | 大屏后排要看清 |
| 汇报 / 方案 | 短语卡 18px，散文 21px | 汇报以 4–12 字短语卡为主，成句导语仍 21px |
| 学习材料 | 21px | 读者自读，句子完整 |

- **图元豁免**：表格单元、坐标轴标签、框图内文字、截图内文字保持原字号（默认 15px），不抬到地板——放大即破图 / 溢出。
- **判别法**：`font-size < 地板` 且带 `line-height` 的是散文（要抬）；单行 label、表格单元、chip 是图元（保留）。
- 抬字号后溢出，**原地压不拆页**：① 收 `line-height`（1.55 → 1.35）② 缩图 `max-height` ③ 精简文字；实在装不下再拆页。

## 4. 文案

**标题 = 观点句，不是栏目词。** 每个内容页标题承载这页的核心判断，并写出最关键的技术 / 方法 / 机制名；全部标题连读是完整论证链。可用句式：

1. 判断 + 结果双短句：「X 驱动 Y，带来 Z」
2. 「功能名词：利益句」冒号式：「远程运维：减少上站，让运维简单高效」
3. 「基于 X（技术），实现 Y（效果）」/「在 X 场景需要 Y 技术确保 Z」
4. 案例公式：「案例｜{对象}：{做法}，{价值}」
5. 数字排比即摘要：「三层技术栈，六大领域，22 个方向」

三类反模式：栏目式（「系统架构」「实验结果」）；悬念式（只造气氛）；有判断无技术名词（效果记不到具体技术头上）。标题写不出观点，说明逐页表「核心观点」没想清楚，回去改表。

**正文纪律**：

- 每句有信息量。不写「赋能、极致、重磅、行业领先」类套话；不用自造比喻代替技术描述（「整树换血」→「解析并替换 DOM」）。授课里明确标注的教学类比行例外，但去掉类比后技术句仍须成立。
- **页面上不写操作提示**（「点击查看」「点击切换」）；真实功能控件的短标签（「复制链接」）除外。
- 汇报：短语级碎片为主（4–12 字），完整长句只出现在页顶导语与案例叙述；卡片小标题是四到六字断言（「交付成本高」「迁移能力强」）；关键词**变色不加粗**。
- 排比工整：列表统一句式；痛点页以问句收尾为方案铺垫。
- 引文组件：大引号 + 引文 + 破折号署名（职务全称）。

**数字用法**：数字必大必变色（`--accent` 或深色工作色）+ 小号单位紧贴（「20.8万 员工」）；偏爱「N+」开区间；对比固定「过去（灰小）vs 现在（大字）+ 箭头」；数字必挂口径脚注（来源、截至日期）；敏感金额脱敏保留百分比。

## 5. 页面结构与卡片体系

画布 **1920×1080**；内容页 padding `56px 90px`，门面页 `108px 130px`。内容页四段自上而下：

1. **eyebrow**：小标签 `X.X · 中文 / ENGLISH`，18px，`letter-spacing:.2em`，`--accent`
2. **标题**：46px（密页 40–42），`font-weight:600`，`--fg`
3. 可选**导语**：一两句带信息量的话，`--fg-body`
4. **主体**：`flex:1; min-height:0`——吃满剩余高度且能收缩，这两个属性是版式不塌的关键

**卡片基线**（不逐页发明样式）：

- 大卡片统一 `background:var(--surface); border:1px solid var(--line); border-radius:var(--radius)`；表格、截图、SVG 图元、流程节点不套大卡片。
- **同组同层级同角色的兄弟卡片完全同构**：底 / 边 / 圆角 / 阴影 / 内边距 / 标题与正文的字体族、字号、字重、行距一致。
- 卡片标题无色块底、默认 `--fg`；一张卡只留一层标题；删除不承载业务信息的胶囊、角标、版式说明标签（业务状态、风险等级、单位例外）。
- 只有文案明确表达**选中、推荐、当前、风险、结论差异**时，才允许单卡用 `--accent` 文字 / 底色 / 边框 / 阴影 / 字重；视觉差异必须能从卡片文字读出原因。

## 6. 审美硬要求

1. 不留大块空白：主体 `flex:1` + `justify-content:space-between/center` 撑开或居中；内容不堆在上半页。
2. 图 / 截图按列宽放大填满：近方图填满高框，截图 `width:100%`；小图缩在中间四周留白是最常见败笔。
3. 结论放进对应内容栏，不另起横贯整页的结论条（huawei 风格的「底部结论条」是风格专属组件，按风格文件用）。
4. 跨页统一优先于单页炫技：改一页卡片先审视全 deck。
5. 相邻内容页在 `--bg` / `--bg-alt` 间交替。
6. 密集页（卡片 20+）靠网格对齐与统一卡片维持秩序，密疏交替。
7. 照片直角不圆角；重要图片用风格规定的装饰（如 huawei 红色四角线框），不描整框。

## 7. 术语表

| 术语 | 含义 |
| --- | --- |
| 页型 | 一页的版式模式（`page-patterns.md` 目录条目） |
| 视觉家族 | 页型所属的大类：网格 / 分栏 / 流程 / 矩阵 / 证据 / 全图 / 观点 / 门面 |
| 密度 | `light` / `normal` / `dense`，控制节奏 |
| 门面页 | 封面、目录、章扉、问题页、致谢 |
| 拍 | 放映时一次推进；拍数 = 页内最大 `data-step` + 2 |
| 占位块 | 初版配图位的类型化标注（`data-todo`） |
| 图元 | 表格单元、轴标签、图内文字等不受散文地板约束的文字 |
| profile | 风格内的浅色 / 深色整套变量取值 |
