# 覆盖审计（wyx:audit）

只读识别规格覆盖缺口，输出补规格的行动计划。它不验证所有行为，也不写规格、地图或历史。限定路径时只审该子树，外部引用单列。

## 发现规格与候选

1. 搜索 `CONCEPT.md / PIPELINE.md / SYNCS.md`，沿总体 PRD 索引找到暂存规格。记录名称、路径、格式及实际管辖范围。
2. 原生 CONCEPT 检查 interactions/dependencies；Jackson 检查四节与可选 notes，缺旧边界段是正常现象，只说明旧 hooks 不注入该内容。PIPELINE 检查 data boundary。
3. 用 `rg --files` 或等价只读工具统计源码目录。忽略依赖、生成物、构建产物及纯测试/类型/配置目录；“同目录源码 >2 且无规格”仅用于优先发现，不能据此漏掉单文件核心模块或断言覆盖率。
4. 结合用途、公开动作、状态归属与生命周期判断候选。已有祖先规格是否实际覆盖要读内容，不能只看文件存在。基础设施不自动成为 concept；API 程序员也可以是概念的用户。

候选类型：

| 证据 | 候选 | 下一步 |
| --- | --- | --- |
| 独立目的及完整行为，拥有可解释的状态 | concept | `wyx:concept <路径>` |
| 可区分的数据转换阶段及质量约束 | pipeline | `wyx:pipeline <路径>` |
| 事件、请求或任务协调概念动作 | sync | `wyx:sync <路径>` |
| 只有类型、工具、框架胶水 | 支撑代码 | 记录跳过理由 |

聚合/join、多个 import、handler 目录名都是搜索线索，不是边界结论。跨概念直接调用同时列为耦合证据；不能因为有公开 API 就认定 Jackson 独立性成立。

## 排序与报告

读取候选的真实依赖。先被依赖者，再管道/sync 消费者；存在循环时把强连通组一起列出并标待拆边界，不能无限等待“叶子”。代码依赖用于回填顺序，不推导产品 extrinsic 依赖。

输出：

1. **已有规格**：名称、类型、路径、方言、有效覆盖范围；缺节及 hooks 限制。
2. **候选/跳过项**：路径、证据、建议类型、理由。所有覆盖率必须附分母定义；未完整枚举模块则不报百分比。
3. **行动计划**：按依赖顺序分批列命令，同批按路径排序。用户未指定细化对象时停在可选候选清单。
4. **下一步**：已有规格的新鲜度由 `wyx:concept drift` 检查；规格更新后由 `wyx:map` 重建地图。只有用户要求更新文档时才进入对应写入模式。

无缺口只表示本次覆盖检查未发现遗漏，不等于模型或代码通过全面审计。需要后者交接 `concept-audit`。
